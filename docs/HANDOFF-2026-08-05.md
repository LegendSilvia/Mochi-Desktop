## The roadblock, and why it is not what it looked like

Semantic recall lives in Mastra's `Memory`, which only the `/chat/:agentId` route
consults. Chats go to `/agent-sdk/chat/:agentId` — the Claude Agent SDK — which
owns its own history and never asks Mastra anything. So every memory switch in
the loadout is wired to a backend the user is not on.

**Mastra's OAuth support does not help.** `MastraAuthGoogle` / Okta / Supabase are
*inbound* server auth — logging users into a Mastra server. Nothing authenticates
outbound to Anthropic.

**The outbound version is barred, not missing.** Per `agent-sdk-route.ts`: Mastra's
router talks to api.anthropic.com and always needs an API key; the Agent SDK
reusing the Claude Code CLI's OAuth credential is the only sanctioned way for a
third-party app to run on a subscription. Lifting that token out and pointing it
at the API would violate the Consumer ToS. **Do not revisit this.**

## The way through

`Memory` exposes `recall()` and `saveMessages()` publicly and does not depend on
Mastra's model router. So the paths split cleanly:

- **Chat** → Agent SDK → Claude Code binary → subscription. Sanctioned, free.
- **Embedding + retrieval** → Mastra `Memory` with the user's OpenRouter key.

No ToS exposure: nothing points an OAuth token at Anthropic's API.

Shape:

```
before the turn:  memory.recall({ threadId, resourceId, vectorSearchString: prompt, threadConfig })
                  -> prepend matches to the prompt (replayPrompt is the existing seam)
after the turn:   memory.saveMessages({ messages })  -> embedded for next time
```

Use the same LibSQL store/vector ids as `agentFromLoadout`, so memory follows the
user across a backend switch instead of forking.

## Verification notes

Drive the app; do not reason about it. Three bugs today surfaced only under a real
run. `cdp.mjs` (in the job tmp dir) drives it over `--remote-debugging-port=9222`.

- Real key events reach the composer; **synthetic React events do not** — setting
  `input.value` + dispatching `input` fails even on untouched controls.
- Sliders could not be driven at all (real drags included). Verify slider-backed
  settings through `settings.json`, not the DOM.
- Never `pkill -f electron`; filter on `CommandLine -like '*electron.exe .*'`.
- Never write JSON the app reads with PowerShell — `Set-Content -Encoding utf8`
  emits a BOM and `JSON.parse` refuses it. Use Node.
