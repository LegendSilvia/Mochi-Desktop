# Handoff — 2026-08-08

Permission modes (phases 1 and 2), MCP authentication, and two pre-existing
holes in the permission system that only showed up when the app was finally
run.

Everything below is on `main`.

## Read this first

**Two things were shipped knowingly incomplete.** They are not oversights and
they are not hiding:

1. `src/shared/consequences.ts` has **one Critical and three Important** open
   findings (see [Open findings](#open-findings)). It is a security boundary
   with known gaps.
2. Auto-with-a-chosen-model **over-cards**. Roughly half of realistic
   multi-field calls now stop at a permission card that should not. The mode
   is opt-in and did nothing at all before, so this is a limitation of a new
   feature rather than a regression — but it is why Auto is not yet pleasant
   to leave on.

Neither blocks the rest. Both are argued in [Where I would go next](#where-i-would-go-next).

## What works, verified in the running app

Not "typechecks" — watched working in Electron on Windows, driven over CDP.

- **Four permission modes per session** — Manual, Accept edits, Plan, Auto.
  Picker in the composer, `1`–`4` shortcuts, persisted per session, live
  mid-turn switching through `setPermissionMode`.
- **Bypass permissions is unreachable.** Not in the type, not in the rendered
  menu, not via a hand-edited `settings.json` (`coerceMode` floors unknown
  values to `manual`). Confirmed against the live DOM, not just the source.
- **Auto with a chosen model** runs Mochi's own classifier; Auto with no model
  runs the CLI's native one.
- **A plan gets a plan-shaped card** and a Plan widget that survives restart.
- **MCP servers can authenticate** — headers and stdio env, values in
  `safeStorage`, never in `settings.json`. A user server can no longer take the
  name `mochi` and displace the built-in tools.
- **`PowerShell` is gated** (see below), and **delegated sub-agents are denied**
  anything outside the auto-approved set.

## The two holes running it found

Both pre-existing, both invisible to five rounds of code review, both fixed and
watched working.

### `canUseTool` is never invoked for `PowerShell` — `0884407`

The SDK's `canUseTool` callback does not cover the `PowerShell` tool. On
Windows — the platform this app targets first — that is *the* shell. So a shell
command ran with no permission card, **in every mode including Manual**, and
neither the consequence table nor the classifier could help, because the
function they hang off was never called.

Reproduced in a temp directory with no `.claude` anywhere, `settingSources: []`,
`permissionMode: 'default'`:

```
attempted: PowerShell   canUseTool saw: (none)   -> BYPASSED
attempted: Write        canUseTool saw: Write    -> gated correctly
```

The `Write` row is the control. Not settings, not cwd, not permission mode, and
not `allowedTools` shadowing.

**The fix.** A `PreToolUse` hook returning `ask` for anything outside
`AUTO_APPROVED`. `ask` routes the call into `canUseTool`, which then fires for
`PowerShell` too. It is a funnel in front of existing machinery — the table, the
classifier, the card and the reasons are untouched.

The hook **must never return `deny`**: a PreToolUse deny bypasses `canUseTool`
entirely, which would route around the card, the classifier and the escalation
reason. `ask` is the only verdict it may give.

### Delegated sub-agents had no gate at all — `568f43e`

`buildMochiServer`'s delegate sub-`query()` had neither `canUseTool` nor hooks,
so a delegated worker could run anything, ungated, in every mode except Plan.
`mcp__mochi__delegate` is auto-approved, which made delegation the way around
the gate the first fix had just added.

**The fix, and the reasoning worth keeping.** A sub-agent has *no user to ask* —
a card there would park a promise nothing can answer and hang the parent until
timeout. So the same policy produces a different outcome: outside
`AUTO_APPROVED`, everything is **denied**.

`assess()` is consulted only to choose the *reason text*, never the verdict.
A table verdict of `allow` means "no objection, the classifier decides" — with
no classifier and no user present the honest answer is still no. Do not let that
drift into "table says allow, so run it".

Delegated workers are therefore effectively read-only, which is what the
`researcher` role already promised. Nothing became impossible; the parent can
still do the write itself, with a card.

## Open findings

### Critical — one normalisation launders what another would have caught

`src/shared/consequences.ts`, in `readings()`. The URL-decode runs on the **raw**
value while everything else runs on the normalised one. A zero-width or NUL
character inside a percent escape makes `decodeURIComponent` throw; the catch
swallows it, and the zero-width strip has meanwhile produced exactly the clean
`%2e%2e%2f…` reading that needed decoding.

```
{p:'%2e%2e%2f%2e%2e%2fetc%2fpasswd'}          -> card
{p:'%2e%2<ZWSP>e%2f%2e%2e%2fetc%2fpasswd'}    -> allow
```

One line to fix — decode the normalised value. It is the **fifth** instance of
one class: *a scan silently saw less than it should, and the default was allow.*

### Important — three more of the same class and its mirror

- **Key adjacent to its own value is invisible.** `{rm: '-rf ./build'}` → allow.
  The joined pass excludes keys, which is right for *interposed* keys and
  silently wrong for this.
- **The joined pass builds only first-of-each and last-of-each readings**, so a
  call needing two different readings at once slips through.
- **Over-correction.** `\bpush\b.*\bforce\b` gained unbounded reach across every
  field, so a Notion page titled "Add push notifications" whose body says "force
  a rebuild" now cards. Key-walking makes URL-style keys — route tables, import
  maps, OpenAPI specs — trip the absolute-path rule.

### Minor

A settings-read failure inside `canUseTool` is labelled `source: 'model'`, so the
card says the classifier stopped something no classifier touched. Eight further
minors are listed in the branch ledger, triaged as safe to defer.

## Where I would go next

**The table's scope is the problem, not any individual bug.** Five fix rounds
each closed a real instance and opened new surface; by the last one the fixes
were colliding with each other in both directions at once — new bypasses *and*
new false positives. Asking regexes to be a general content scanner over
arbitrary nested structures has no natural notion of *"I have seen the whole
input."*

The narrow version that earns its keep:

- **Structural tool tags** — a shell is a shell, judged by what the tool *is*,
  needing no scan. This is the part that already works.
- **Filesystem paths resolved properly**, rather than pattern-matched.
- **Let the model judge argument content.** That is what a model is good at and
  what regexes are bad at, and the table stops being a content scanner.

That is a change to an approved spec
(`docs/superpowers/specs/2026-08-07-permission-modes-design.md`), so it wants a
decision before more rounds go into the current shape.

**Also open:** the delegate sub-`query()` is now gated but still has no way to
*ask* — a nested approval has no UI. Read-only is the right default; if a
delegated write is ever wanted, that needs designing.

## Phase 3, unwritten by design

The Mastra/API-key backend still ignores mode entirely. Its picker says so on
screen rather than pretending. Per the spec, `assess()` alone is the whole
decision there — no classifier — which is why the table was written to serve
that case unchanged.

## Testing reality

The repo has no test runner. Pure modules are proved by Node scripts:

```
node scripts/check-consequences.mjs      # 436 assertions
node scripts/check-permission-modes.mjs  #  15 assertions
```

**Read this before trusting them.** The consequence table's suite passed against
*three* separate Critical bugs, because its test data was uniformly simpler than
real data — single-property objects, single-line strings, no argv arrays, no
path-keyed maps. It now carries those as standing shapes. The lesson generalises:
test data simpler than production data proves less than it appears to.

Two eslint errors in `src/renderer/src/components/shell/CommandPalette.tsx`
predate all of this. ~10.8k CRLF prettier warnings are a checkout artifact —
never run `npm run format`, it rewrites the repo.

## Still unverified

Everything below needs a human at the keyboard:

- The plan card and the Plan widget end to end.
- Whether a *denied* `ExitPlanMode` really arrives with `is_error` set. The type
  chain is verified; the denial's wire construction happens in a compiled
  subprocess. Safe either way, just less informative if not.
- Whether supplying `env` to a stdio MCP server replaces or merges the child
  environment. The upstream MCP SDK uses `params.env ?? getDefaultEnvironment()`,
  which would strip `PATH` — if Claude Code does the same, adding one credential
  breaks a working `npx …` server.
- The Mastra backend's behaviour under any of this (it ignores mode, so: nothing
  should change).
